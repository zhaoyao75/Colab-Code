# 团子猫日常：经验总结（第1、2集）与第3集交接

## 一、已确定的系列规格（不要改）
- 画幅/规格：1080×1920，30fps，H.264 High + AAC 立体声48kHz，-14 LUFS（实测会偏响，需再降约1–4dB，直到实测 -14.0~-14.2），峰值<-3dB，faststart，约4–6MB。
- 风格：布达佩斯粉紫配色（粉墙渐变+白点、紫地板、红地毯条+金边、浅蓝架子/桌），奶油色圆团猫，深李子色描边 #3b2040，站酷快乐体字幕（OFL，可商用），少女配音（edge-tts zh-CN-XiaoyiNeural），真实猫叫素材（ESC-50，CC BY-NC，商用需换）。
- 主人 = 抽象紫色剪影，手臂是同色圆润长条，无手掌手指。
- 结尾卡 = 居中奶油卡片：黄色小标签「团子猫日常 · 第N集」+「下集预告」+ 大标题 + 小插画；不放“关注”按钮。第2集结尾预告「下集：团子猫洗澡」。
- 时长 10–12 秒；0–2 秒必须有“反差感”钩子（软萌外形 × 冷淡/狠话台词），不能只靠卖萌。

## 二、用户的明确偏好（踩过的坑）
1. 情节不要幼稚：不要蹦跳摔跤闹剧、星星眼爱心泛滥；爱心要少且随机，不排成排。
2. 两集不能套路相似：第1集偷蛋糕→被抓→奖励；第2集改成“嫌贵窝、爱纸箱”（无偷、无抓包、无奖励）。第3集必须再换骨架。
3. 风格不能大改：试过“犯罪纪录片+黑边+男声”被否决，要保持原有可爱风格，只改分镜/节奏/笑点。
4. 猫叫：少而准（每集1–2声），不要密集；合成猫叫太假，用真实录音。
5. 发抖/抖动：轻微即可（幅度约±1°）。
6. 猫走路不要整体蹦跳，要有两只脚垫交替迈步、落地不滑。
7. 配音说“下集，团子猫洗澡。”，不要“收工”“关注看下集”。
8. 字幕全角标点在站酷字体里间距怪，尽量少用“！！”“……”。
9. 封面分辨率要求：最低 640×854；给 PNG（用户明确要过 PNG）；竖版9:16、3:4主页裁切、合集方形1080×1080、横版4:3都要过。
10. 每次交付要如实说明：只抽查了关键帧、没听过声音、素材许可风险。

## 三、技术流程（可复用）
- 全部用代码做：SVG 场景（单个 HTML，`R(t)` 函数按时间渲染）→ Playwright 截图成序列帧（6 个进程并行，每进程 i%6）→ ffmpeg 合成。
- 渲染注意：HTML 必须有 `<meta charset="utf-8">`，否则中文乱码；等字体加载 `document.fonts.load`；后台渲染要按真实帧数等待，别用旧的 .done 标记。
- 配音：edge-tts 需要 `certifi.where=lambda:'/root/.ccr/ca-bundle.crt'` 才能过代理证书；每句用 silenceremove 裁首尾静音，量时长后再排时间线。
- 声音：numpy 合成 BGM+音效；配音时 sidechaincompress 压低 BGM；猫叫用 ESC-50 数据集（raw.githubusercontent.com/karolpiczak/ESC-50，category 5 = cat，自动切单声）；响度 loudnorm 两遍后再实测微调。
- 钩子音频设计：开场几乎无声（只一个低沉“咚”），目标揭晓后才起音乐；结尾音乐戛然而止再接预告，形成反差。
- 封面：同一场景代码出图，deviceScaleFactor=2 出高清，ffmpeg 缩放/裁切；3:4 裁切时标题和猫要放在中间安全区。
- 验证：每次渲染前先出关键帧拼图目视检查（常见问题：遮挡、被边缘切掉、气泡压脸、文字叠在一起）。

## 四、第3集方向
- 主题：下集预告已承诺《团子猫洗澡》。
- 骨架必须区别于“偷吃被抓”（第1集）和“嫌弃送礼”（第2集）。建议先给用户 2–3 个分镜方案（带 1.6 秒内的反差钩子），确认后再做成片。
- 结尾预告下一集的题材需要用户确认（不要自己编后再当成定案）。
